- 1: Contrat de machine abstraite = fondation non négociable de la portabilité (x86-64, AArch64, AArch32, Cortex-M, RV32, RV64). Le cœur ne suppose du matériel que ce qui est explicitement listé ; tout le reste est interdit. Trois familles de contraintes, hiérarchisées par irréversibilité :
  A) Représentation (PRIMAUTÉ : seule famille inter-nœuds et irréversible — casse chez l'autre, sur une donnée déjà signée/propagée → fork du réseau, pas un bug local).
     Règle racine unique : une représentation mémoire choisie par le compilateur ne doit JAMAIS devenir une donnée observable. Frontière : à l'intérieur du cœur le layout appartient au compilateur (libre, jamais inspecté) ; à la frontière (réseau, stockage, hash, signature) le layout appartient à la spec, octet par octet, aucune `struct` C n'y apparaît.
     Corollaire opérationnel suffisant : aucun memcpy/cast entre `struct` et buffer d'octets, dans aucun sens, jamais → endianness (LE/BE8/RV), padding, alignement strict, largeur 32/64 (`int`/`long`/`size_t`/`uintptr_t` bannis des formats), signedness de `char` (signé x86 / non signé ARM), ordre des bitfields, taille des enums cessent mécaniquement d'être des problèmes. Zéro UB toléré (overflow signé, shift ≥ largeur, type punning/aliasing).
  B) Environnement (auto-détectable au build/link, local, réversible) : cœur freestanding — pas d'OS, libc, FS, sockets, stdio, errno ; pas d'allocation dynamique (mémoire fournie par l'appelant) ; pas de flottant (pas de FPU partout + non reproductible donc incompatible avec un hash) ; pile bornée (pas de récursion, VLA, alloca) ; aucun thread créé ou possédé par le cœur.
  C) Ordre & temps (exécution, dégrade un nœud, largement évitable par design mono-flot) : modèle mémoire faible par défaut (ARM/RISC-V vs TSO x86) ; atomiques non garanties (Cortex-M0 sans LL/SC → seule primitive universelle = masquage d'interruptions) donc synchronisation uniquement via primitive abstraite du port ; aucune horloge supposée (le temps est une entrée fournie, jamais lu par le cœur).
  Justification de l'ordre : A définit ce qu'EST une donnée ; B et C ne définissent que comment on l'exécute. En P2P sans autorité, la représentation canonique EST le protocole (identité = hash d'octets, aucun arbitre pour deux interprétations des mêmes bits).
  Critère de vérité : un cœur jamais compilé/exécuté ailleurs n'est pas portable, il est « pas encore cassé » → CI build+tests sur les 6 cibles, plus au moins une cible big-endian et une strict-align, avec les mêmes vecteurs de test octet-exacts.
  Conséquences dérivées (à traiter ensuite) : la couche port/HAL n'est que la liste fermée issue de ce contrat ; l'encodage canonique n'en est que l'application aux données ; les profils de nœuds (full/light/constrained) en découlent.
